ConceptsHow the parts fit

The class never reads an Excel or JSON file itself. Every run goes through one plain text file in the Windows temp folder, and MIEConvert.exe turns that file into the real format or back. The class only knows how to read and write that one text file, and the helper only knows files — neither knows about the other's job.

StepExportImport
1The class walks the table (in primary key order) and writes the selected fields to a temp file.The class runs MIEConvert import, which writes the source file as a temp file.
2It runs MIEConvert export, which writes the CSV, JSON, XML or Excel file.The class reads the temp file row by row, fills the record buffer and inserts or updates.
3The temp file is deleted.The temp file is deleted.

The intermediate file

Tab separated, one record per line, CRLF line ends, Windows ANSI. Inside a value only four characters are escaped: \\, \t, \r and \n. The first line holds the column names. On export a second line holds one type code per column — S string, N number, D date, T time — so the helper can write real Excel number, date and time cells.

Id	Name	Since	Alarm	Balance
N	S	D	T	N
1	Smith, John	2020-01-02	08:30:15	1234.56
2	Say "Hi" \ttab\\back			-42.5
3	Line1\r\nLine2	2024-02-29	23:59:59	0

ConceptsFields and columns

Each AddField call adds one row to the Fields queue: the field's label, its default column name, its dictionary type and picture, and an ANY reference to the field itself. Everything the window shows and everything Export and Import do is driven by that queue.

Queue fieldUsed for
SelectedExport: the column is written. Import: the field is filled.
OrderExport column order. Move Up / Down swaps it; the queue is kept sorted on it.
HeaderExport: the column name written. Starts as the field's name.
SourceNameImport: the name of the source column mapped to this field.
SourceColImport: that column's position in the current file, worked out again by ResolveMap on every run.
IsKeyPart of the primary key: Add-or-update and Update-only find records through it.

Mapping is kept by name, not by position, so a file whose columns come in a different order next month still imports correctly.

Auto Map

Auto Map compares names after removing the prefix (CUS:), case, spaces, underscores, dashes, dots and brackets. Cust Number, CUST_NUMBER and CUS:CustNumber all match. A field matches on its name, its label or its current header. When the file has no header row, the columns are called Column1, Column2 ... and Auto Map pairs them with the fields by position.

ConceptsImport modes

ModeEquateWhat happens to each row
Add new recordsMIE:Import:AddInserted. A duplicate key is counted as failed.
Add or updateMIE:Import:UpsertThe primary key from the row is looked up. Found: the mapped fields are written over the record and it is updated — unmapped fields keep their values. Not found: inserted.
Update existing onlyMIE:Import:UpdateAs above, but a row with no matching record is skipped.
Replace all recordsMIE:Import:ReplaceEvery record of the table is deleted first, then each row is inserted.

The two update modes need the primary key: the table must have one, and its fields must be mapped. When no key field is mapped, new records are primed — under ABC that gives them the next auto-increment number. When the key is mapped, the imported key values are kept.

Excel sheets

On import, LoadSheets lists the sheets and SheetName picks one (blank = the first). Excel's first non-empty row is the header and completely empty rows are skipped. On export, SheetName names the new sheet. With ReplaceSheet on an existing .xlsx, only that sheet is added or replaced and every other sheet keeps its content and formatting — so one workbook can collect several tables, one per sheet.

How-toRunning without a window

Everything the window does is a property and a method call, so scheduled jobs and services use the same class. Call LoadColumns and AutoMap (or MapField) before Import: the mapping is by name, and the class has to see the header first.

MIE        MyImportExportClass
  CODE
  MIE.Init()
  MIE.Silent  = 1                         ! no message boxes
  MIE.IniFile = ''                        ! do not touch the INI
  MIE.SetTable(Customer, 'Customer', CUS:KeyId)
  MIE.AddField('CUS:Id',   'Id',   'LONG',   '@n_10', CUS:Id, 1)
  MIE.AddField('CUS:Name', 'Name', 'STRING', '@s40',  CUS:Name)

  ! nightly export
  MIE.Format    = 'XLSX'
  MIE.FileName  = 'c:\exchange\customers.xlsx'
  MIE.SheetName = 'Customers'
  IF MIE.Export() THEN Log('export: ' & MIE.ErrorText).

  ! morning import of the changes
  MIE.Format     = 'CSV'
  MIE.FileName   = 'c:\exchange\changes.csv'
  MIE.ImportMode = MIE:Import:Upsert
  MIE.LoadColumns()                       ! read the header row ...
  MIE.AutoMap()                           ! ... and map it by name
  IF MIE.Import()
    Log('import: ' & MIE.ErrorText)
  ELSE
    Log(MIE.ResultText())
  END
  MIE.Kill()

How-toRules and custom table I/O

Every read and write on your table goes through a virtual method, so you change behaviour by deriving. ValidateRecord runs after the row is in the record buffer and before it is written — return non-zero to skip the row, or fix values on the way in. ExportFilter decides record by record what is exported.

MIE        CLASS(MyImportExportClass)
ValidateRecord PROCEDURE(),BYTE,DERIVED
InsertRecord   PROCEDURE(),BYTE,DERIVED
           END

MIE.ValidateRecord PROCEDURE()
  CODE
  IF CUS:Email = '' THEN RETURN 1.        ! skip the row
  CUS:Email = LOWER(CUS:Email)            ! clean it up on the way in
  RETURN 0

MIE.InsertRecord PROCEDURE()
  CODE
  CUS:CreatedOn = TODAY()
  RETURN PARENT.InsertRecord()

The template does exactly this for you, routing the I/O through ABC's Access: and Relate: objects and giving you embed points in each method. See the Template Guide.

How-toErrors and results

Export, Import, LoadColumns and LoadSheets return 0 when they ran. Otherwise ErrorText says why — including the helper's own message, such as a sheet that does not exist or an .xls that is too big. A run that worked can still have refused rows: check Failed and LastFailure. ResultText puts it all in one message.

Processedrecords writtendata rows read

Clarion notesThings the language does to you

Behaviour that belongs to Clarion rather than to this library, found the hard way while building it. Each one cost real time; they are here so they do not cost it again.

An ANY in a queue is shared

The field queue holds an ANY reference per field. Setting Q.Ref &= NULL before CLEAR(Q) to add the next entry changed the entries already in the queue: every field ended up pointing at the last one added, and the first export wrote the same value into every column. Do what ABC's FieldPairsClass.AddPair does — CLEAR(Q), then &=, then ADD — and NULL the references only when tearing the queue down.

Zero-length slices

S[1 : 0] is not a safe empty string. Wherever a line may be empty the class passes one byte more than the line (LineBuf[1 : LineLen + 1]) and the callee subtracts it, and the line buffer always keeps one spare byte so that slice stays inside it.

@T4 pads with a space

FORMAT(t, @T4) gives  8:30:15 with a leading space. ISO times need @T04, which zero-pads to 08:30:15.

RUN and RUNCODE

RUN(cmd, 1) waits for the helper and RUNCODE() returns its exit code. RUN starts the process directly — no command shell — so a ; or | in a quoted argument is passed through untouched, and the helper is built as a windowless exe so nothing flashes on screen. Its error text comes back through a file (--errfile), since there is no console to read.

The class needs the DOS driver

The temp file is read and written in 32 KB blocks through a DRIVER('DOS') file. A project without the DOS driver fails at link time with Unresolved External DOS; the global extension adds the driver for you.

The temp file is ANSI

Clarion strings are single-byte, so the intermediate file uses the Windows ANSI code page. Characters the code page cannot hold arrive as ?. The helper reads UTF-8 and UTF-16 sources fine; it is only the hand-over to Clarion that is limited.

ABC TryInsert renumbers

On a table with an auto-increment key, ABC's TryInsert always gives the record the next number, throwing away an imported key. The generated hooks therefore insert with a plain ADD when the key column is mapped, and through TryInsert (after PrimeRecord) when it is not. Likewise Relate: deletes cascade through the dictionary's relations; Replace all deletes through Access: unless you choose otherwise.

Template pitfalls

  • #IF treats the string '0' as true. Compare explicitly, or keep flags numeric.
  • A #GROUP swallows everything after it, so all groups live in the .tpw, included at the very end of the .tpl.
  • The registry finds template files through the redirection file. Registering straight from a repository folder fails with Could not open include file; install into accessory\template\win first.
  • #? lines are written in column 1 unless indented inside the line itself.
