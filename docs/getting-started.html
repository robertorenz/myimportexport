Volume 1

Getting Started

Install the template, put Import and Export buttons on a browse, and move your first table in and out of Excel.

6 file formats3 templates1 helper exev1.0

OverviewWhat it does

MyImportExport lets the users of a Clarion program move the data of any table in the dictionary in and out of CSV, TSV, JSON, XML, XLSX and XLS files. One window does both directions. The user picks a file, an Excel sheet if there is one, ticks the columns to use and lines each column of the file up with a field of the table. The settings are remembered per table, so the next run of the same job is two clicks.

Template

Writes a procedure MIE_ImportExport(table, mode) that knows every table and field in your dictionary, and drops Import / Export buttons on your browses.

↓
Clarion class

MyImportExportClass: the window, the mapping, the import modes, the type conversion, and the reads and writes on your table.

↓
Helper

MIEConvert.exe: reads and writes the six formats. A single 110 KB program; Excel does not need to be installed.

Step 1Install

From the repository folder run the install script. It copies the files into your Clarion installation and registers the template.

pwsh .\install.ps1                      # or: pwsh .\install.ps1 -ClarionRoot D:\clarion12
FileGoes to
template\win\MyImportExport.tpl, .tpwaccessory\template\win
libsrc\win\MyImportExport.inc, .clwaccessory\libsrc\win
bin\MIEConvert.exeaccessory\bin

Restart the IDE

The template registry is read when the IDE starts. If Clarion was open while you installed, close and reopen it before you look for the templates.

Step 2Add it to an app

  1. Open the app, Global → Extensions → Insert → MyImportExportGlobal. The defaults are right for a single-EXE app.
  2. Open a browse procedure, Window designer → Control Templates → MyImportExportButtons. Place the two buttons where you want them.
  3. Generate and run. Click Export... on the browse.

The buttons work on the browse's table. The global extension made the procedure behind them, MIE_ImportExport, which you can also call from anywhere yourself:

MIE_ImportExport('Customer', MIE:Mode:Export)   ! straight to export
MIE_ImportExport('')                            ! the user picks a table first

Step 3Your first export

  1. Action is already Export. Pick a Format — XLSX is the default.
  2. Click ... next to File and choose where to save. The extension follows the format.
  3. For Excel, type a Sheet name, or leave it blank for Sheet1.
  4. In the field list, untick what you do not want (double-click or Space). Change a Column header in the box below the list, and reorder with Move Up / Move Down.
  5. Click Export. A message tells you how many records went out.

Dates come out as real Excel dates, numbers as numbers, and the header row is bold.

Step 4Your first import

  1. Switch Action to Import and choose the file. The sheets and columns are read at once.
  2. Pick the Sheet. Columns whose names match a field are mapped already; the Sample column shows a value from the first row so you can see what you are mapping.
  3. For a field that did not match, select it and choose its Source column below the list.
  4. Choose the Import mode: add new records, add or update by primary key, update only, or replace all records.
  5. Click Import. The result shows rows read, added, updated, skipped and failed.

Several tables at once

Tick Show the "Export tables..." button on the buttons control template, or call MIE_ExportTables(). Tick the tables, choose XLSX and a file, and click Export: each table becomes a sheet named after it. JSON gives one collection per table and XML one element per table; CSV and TSV write one file per table.

To skip the ticking next time, click Save as... next to Favorite and give the set a name, such as Month end. The favorite keeps the ticked tables, the format and the file. Next time, pick it from the Favorite list and click Export. Delete removes the chosen favorite.

To skip the window too, populate the MyImportExport - Run a favorite (no window) control template on any window and type the favorite's name: one click exports it.

Replace all deletes first

Replace all records empties the table before it adds the rows, and asks first. Use it for lookup tables you reload from a master file.

Without the templateThe smallest program by hand

The class works on its own. Name the table, offer its fields, open the window:

  PROGRAM

  INCLUDE('MyImportExport.inc'),ONCE

  MAP
  END

Customer   FILE,DRIVER('TOPSPEED'),NAME('customer.tps'),PRE(CUS),CREATE,THREAD
KeyId        KEY(CUS:Id),PRIMARY,NOCASE
Record       RECORD
Id             LONG
Name           STRING(40)
Since          DATE
Balance        DECIMAL(11,2)
             END
           END

MIE        MyImportExportClass

  CODE
  MIE.Init()
  MIE.SetTable(Customer, 'Customer', CUS:KeyId)
  MIE.AddField('CUS:Id',      'Id',      'LONG',    '@n_10',   CUS:Id, 1)
  MIE.AddField('CUS:Name',    'Name',    'STRING',  '@s40',    CUS:Name)
  MIE.AddField('CUS:Since',   'Since',   'DATE',    '@d17',    CUS:Since)
  MIE.AddField('CUS:Balance', 'Balance', 'DECIMAL', '@n-14.2', CUS:Balance)
  MIE.LoadMap()                    ! what was used last time, if anything
  MIE.Ask()                        ! the import / export window
  MIE.Kill()

Set the two project defines so the class is compiled into the program, and add the DOS driver to the project:

_MIEDllMode_=>0;_MIELinkMode_=>1          ! Project > Properties > Compiler > Defines

DeployingShipping your program

  • Put MIEConvert.exe next to your program's exe. The global extension can copy it to the output folder on every build (Helper & INI tab).
  • Saved mappings go to your program's INI file (ABC: INIMgr.FileName), in one [MIE_<table>] section per table.
  • Nothing is registered and nothing is installed: the helper is a plain exe.
